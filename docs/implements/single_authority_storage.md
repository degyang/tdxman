# 单一权威存储整改

基线：`f00a1b0`。本轮由 2026-09-30 的实际数据差异触发。

## 问题与约束

公共接口契约与物理布局是两个独立契约。接口字段、单位、缺失值、顺序和错误语义通过存储适配层保持；
它们不能成为保留两套生产派生表或两套参考因子的理由。原布局 2 将计算结果先写旧库，再复制到新库，
属于未完成的存储迁移。9/29 的 292 条 MA20 差异是已经发生的问题，不能只描述为风险。

只读核对覆盖 9 月的 116,775 条股票派生、全部市场汇总、股票因子、锚点及 ETF 因子。
292 条镜像 MA20 均为空，旧库指标均与当前独立复算相同。历史快照显示这 292 条的因子更新均发生在
旧镜像与新指标的更新时间之间。过程日志不足以确定遗漏复制的具体中断点。

## 最终存储职责

| 数据 | 唯一生产存储 |
|---|---|
| 股票日线、来源公司行为事件 | `stocks.sqlite` |
| 股票因子、外部锚点、ETF 因子 | `adjustments.sqlite` |
| 股票派生、日级市场汇总 | `features.sqlite` |
| 指数/ETF 日线 | 各自的原始行情库 |
| 财务、股东人数 | `fundamentals.sqlite` |

布局 3 不在 `stocks.sqlite` 保留 `daily_features/market_daily_summary`，不在公司行为表保留
`factor/factor_anchor`，不在 `etfs.sqlite` 保留因子副本。正常日更直接修改对应唯一存储，取消镜像复制。
计算代码可使用统一的逻辑关系名；映射必须集中、确定、可测试，不允许按文件是否存在猜测布局。
布局访问失败明确报错，不回退旧库。旧生产文件仅作为池外、已验证的恢复点保留。

## 一致发布

每次有界写入在池写锁下完成。原始、参考和派生写入涉及多个 WAL 数据库，不能仅凭 ATTACH/池锁声称
崩溃原子性。提交前持久化本次真实变化的完整行后像及删除键；提交后验证这些行和发布版本，才完成发布。
未完成意图阻止读取和下一次写入；显式恢复幂等地前滚本次意图，验证后解除阻塞。无变化不生成意图，
不改版本、时间戳。计算阶段失败在持久化意图之前回滚；意图持久化后不能把失败误报成“未写入”。

维护入口与日更必须使用同一存储和发布机制。迁移只在已验证的恢复点和排他的池锁下执行，完成后检查
所有权威表、公共接口和旧表退役；不能用全局 READY 或相同行数替代内容验证。

## 验收与以后变更的约束

1. 同一输入的公共 API 值、类型、单位、NULL 和排序与迁移前一致；已知错误镜像按旧权威计算结果纠正。
2. 原始事件、完整因子证明 payload、外部锚点、派生和汇总在迁移中不丢失。
3. 不再存在第二份可写派生/因子表；所有维护入口通过共同发布机制，旧镜像入口在布局 3 不执行复制。
4. 写入失败和提交中断的每个边界可恢复；坏意图、布局错误和缺失库均拒绝读取。
5. 原始报价、无交易状态、无事件因子推进、历史事件修订、汇总修补分别验证；重复执行保持业务哈希和版本。
6. 存储设计变更必须同时给出唯一所有者、全部读写入口、迁移/恢复、旧对象退役及契约测试。
   两套生产权威不能以“兼容”或“回滚期”无限延续。跨设备部署需记录代码与数据布局匹配，不能只同步源码。
