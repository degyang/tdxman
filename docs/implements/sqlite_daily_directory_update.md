# 日更名单、状态与修订处理

> 数据分层术语以[基础数据与 Enriched 数据分层契约](../design/data_layers.md)为准：历史 K 线、下载的复权依据、财务等属于基础数据；计算出的复权因子、逐股衍生、市场/板块聚合及计算快照属于 Enriched 数据。


2026-09-28。用户授权按 tick 的日更顺序设计并执行；本文件记录本轮实现边界，实库结果另附执行回执。

## 固定入口与顺序

`aspool update --root data` 默认 TDX；BaoStock 仍仅由 `--source baostock` 显式选择。TDX update 使用当日报价，历史 K 线仍使用有明确起止日期的 sync。

1. 通过 MAC 的 SH、SZ、BJ 分类目录按代码分页，读取市场、代码、名称；逐页检查重复、市场和字段，限制每市场最多 10,000 个代码。
2. 成功市场的当前名单更新现有 `catalog.duckdb` 目录。某市场读取失败，保留该市场旧名单用于降级采集，报告 partial；旧名称不冒充当天 ST 依据。未返回不自动认定退市，不删除历史。
3. 为缺失上市日期的证券通过 TDX 财务接口获取 `ipo_date`。已知未来上市或已经退市的证券退出今日报价请求，并独立报告。将可靠上市日和交易日历计算出的上市交易日数传给派生计算。
4. 获取今日报价。成功返回、日期匹配、数值有限且非负的零成交快照归为 `NO_TRADE`；无返回或日期过旧按读取失败重试；负数、矛盾 OHLC 等非法输入单独报告。没有把零成交快照断言为交易所确认停牌。
5. 当天名单名称确定 ST/*ST 或摘帽，保存为当天日期事实。即使没有 K 线，也保存 `source_is_st` 与来源；缺行情为 `MISSING`，零成交为 `NO_TRADE`，二者统计均按既定无交易规则处理。已有可靠成交行不被空响应删除或覆盖为无交易。
6. 当日行情、日期事实、近期事件修订、选定因子及受影响逐股派生和日汇总在现有 SQLite writer 中提交。股票业务表仍是四张，不引入新发布平台。

## 事件修订

参照 tick 的成功输入 keep-last 语义，默认检查输入起点之前 14 天至本次末日的事件；TDX 只提供整股事件接口，网络读取其事件记录后立即裁剪到此窗口，日线不因而扫描全部历史。

- 同源相同事件键的新值正常 UPSERT，不再因“与旧值不同”拒绝。没返回旧事件则保留，不自动撤回。
- TDX 的 2–10 类股本变动保存并合并，不重复施加除权价格调整；1 类现金分红、送配变化从最早变化事件之前的选定因子继续计算，重建有限后缀。保留此前因子尺度和原始因子锚点，修订后的选定因子记录派生来源。扩缩股、权证等其他类别仍明确拒绝，不猜测算法。
- 因子变化触发参考昨收、MA20、连板及日期汇总的现有依赖重算。不存在可信原始因子锚点时保持未知，不补 1。
- 输入事件窗口最多 31 个自然日，因子后缀及派生继续受 60 个交易日、事务时间与行数预算约束。需更长跨度的修订报告为未完成，交显式维护，不自动扩成全历史任务。
- 单证券业务输入拒绝时，失败事务先回滚，再剔除该证券输入，提交其余独立证券。数据库故障和事务超时不自动重试，避免掩盖运行错误。

目录是当前元数据，SQLite 是日期事实和行情。目录提交成功不代表行情更新成功；CLI 报告同时记录目录、上市资料、报价分类、证券拒绝及实际提交结果。当前名称不倒填旧日 ST，当前股本不倒填历史换手率。

## 验证范围

新增验证覆盖：名单新增证券、未来上市排除、名单失败降级、无交易/ST 和摘帽事实、上市日传递、同源事件修订、空响应保留事件、因子后缀及汇总更新、非法证券隔离、重复执行零写入。已有测试仅重跑受本轮修改影响的部分。

生产运行前保留一致恢复材料，实库执行放 tmux；日志和恢复材料放 `.local/`，运行 `data/` 保持干净。真实采集完成后独立核对名单分类、逐股派生、两种 scope 汇总及公开读取；不把模拟测试通过当成生产执行完成。

## 2026-09-28 执行回执

实现和实库执行完成，代码仍在工作区，尚未提交、构建新版 wheel 或部署到其他设备。股票业务表保持四张，公开读取接口未变。使用本地 tick-stock-panel `d71cafc` 的名单优先、成功输入 keep-last 和零成交过滤语义；没有照搬其整文件替换与全历史 enriched 重算。

```sh
# 正常每日入口：名单 → 当日报价 → 日期事实/因子 → 涨跌停及市场公共特征
.venv/bin/aspool update --root data --workers 1 --retries 2 --retry-delay 1

# 定向续跑仍用同一入口，只处理指定证券的行情、事件与派生
.venv/bin/aspool update --root data --symbol 000420.SZ
```

内部编排签名为 `run_update(root, *, source="tdx", symbols=(), limit=None, start=None, end=None, retries=2, retry_delay=1.0, now=None, report=None, mode="update", workers=4)`。历史 `sync` 保留明确起止日期和 K 线数据源；备用源只由 `--source baostock` 选择。目录写入先比较小型元数据表，只对变化项 UPSERT，重复日更不执行数千次无变化的逐行写语句。

21 只零成交包含之前误报读取失败的 13 只及本次名单新增的 8 只。它们有带当前日期的零成交报价，只证明当天无成交，不等于交易所已确认停牌。9 只没有可用 IPO 日期：`001246.SZ、301569.SZ、301660.SZ、301716.SZ、301718.SZ、920157.BJ、920162.BJ、920196.BJ、920202.BJ`，均属本次无交易证券；未凭猜测标成未来上市，CLI 仍通过 metadata.failed 披露。现有已上市证券不再依赖猜测上市天数。

161 只没有已验证因子锚点，其中 152 只有当日成交、9 只无交易；保持未知，不补因子 1。成交证券 MA20 可用 5,405 只。这些既有缺口、可选质量 JSON 列升级、指数/ETF 日更及 Jakarta 复制不属于本轮已完成事项；Fundwise 的自有评分缓存也没有由此命令自动重算。

- 分轮定向验证 53 个不同用例；覆盖名单/上市过滤、零成交 ST 及摘帽、事件类别/修订、事务回滚、无效证券隔离和受影响的既有 update/sync/质量接口。只在修改、失败或新增覆盖时重跑，没有执行全仓重复测试。Ruff 和 diff 空白检查通过。
