## 实测瓶颈与优化

首次真实全市场日更耗时 715.39 秒，峰值 RSS 217,580 KiB。股票阶段约 643.88 秒；
writer 累计 457.42 秒，其中市场截面汇总 417.54 秒，单股计算器 6.44 秒；镜像另耗 148.69 秒。
汇总和镜像各执行 264 次。嵌套计时有包含关系，不能把 writer 与其内部计算再次相加。

此前 cc 的 SQLite 内部 reconcile 复制和浅/深校验分层优化保留。本次针对真实日更重复处理：

- 最多 128 只已由当日昨收确认的相邻无事件因子后缀，与本批原始行情一起提交；逐股派生、
  市场汇总和分层镜像各处理一次。历史事件修订仍在行情提交后逐股隔离，SDK 大批的剩余
  无事件后缀仍按 32 只提交。30 秒事务预算未增加。
- 因子校验失败只移除其因子输入，再提交有效行情；数据库或预算错误回滚并直接传播，
  不当作证券错误重试。写入和镜像继续共用池锁及上一镜像 READY 门闩。
- 原始版本没有变化时，确认上一镜像完整后直接跳过镜像，保留业务行、时间戳与版本。
- 子报告持续记录采集、事件读取、writer、逐股派生、市场汇总和镜像耗时；修正原批次
  `elapsed_ms` 未包含后续独立因子事务的问题。

在隔离的完整历史库（约 1,636 万股票派生行、当日全市场截面）回放同一批 384 只股票：

| 指标 | 原流程 | 优化后 |
|---|---:|---:|
| 两轮耗时 | 65.60 / 61.61 秒 | 15.93 / 14.79 秒 |
| 中位耗时 | 63.60 秒 | 15.36 秒 |
| 汇总 / 镜像次数 | 15 / 15 | 3 / 3 |
| 逐股派生处理行 | 768 | 384 |
| 显式计算读取行 | 97,479 | 24,411 |

中位耗时降低约 75.8%，约快 4.14 倍。每轮重置相同准备状态，按“原、新、新、原”顺序执行；
全部原始行情、因子、派生与市场汇总业务字段（排除运行时间戳）相同，今日镜像连同时间戳一致。
无变化回放耗时 1.56 秒，镜像提交 0；关闭并 checkpoint 后三个业务库文件哈希不变。
这是本地热工作集、无事件子集回放，不含网络和历史事件修订，也不是下一新增交易日的全市场 SLA。
