## 命令及数据维度

```sh
# 默认通达信收盘报价，直接读取量比、换手率等当日指标。
aspool update --root data --type all
aspool update --root data --symbol 000001.SZ --retries 2 --retry-delay 1

# BaoStock 仅在显式选择时使用，不是默认第二阶段。
aspool update --root data --type stock --source baostock --status missing

# 通达信历史 K 线；缺失量比和换手率随局部写入补算。
aspool sync --root data --source tdx --period daily \
  --start 2026-09-23 --end 2026-09-24

# 显式补齐全部数据块：目录、指数/日历、股票/派生、ETF、财务快照。
aspool sync --root data --type all
```

`update` 使用 MAC `get_stock_quotes`，不调用历史 K 线；`sync` 使用 `get_stock_kline`，不把当前报价名称/ST/股本倒填历史。两条路径都调用 SQLite 局部 writer，更新日线、必要因子区间、逐股派生和两种 scope 的日市场汇总。Regime 公共输入含涨跌分布、连板、晋级、MA20 广度等；Fundwise 自己的评分及阶段模型由消费端处理缓存更新和重算。

TDX `update` 先分页刷新沪深北当前名单，再采集当日报价。当天名称进入当天 ST 事实；无 K 线也可保存 ST/摘帽。缺上市资料时读取财务接口的 IPO 日期，排除明确未上市或已退市证券，传递上市交易日数。失败市场保留旧名单降级请求，旧名称不充作当日依据。

默认数据根目录为当前目录下的 `data/`，不自动创建或迁移数据库。`update` 和 `sync` 都支持 `--type stock|index|etf|all`；`all` 先刷新股票与 ETF 名录，再依次更新指数/交易日历、股票/派生、ETF 与财务快照。新 SQLite 路径拒绝 `--no-enrich`，避免写入未同步派生的日线。

旧 `update --baostock/--no-baostock/--lookback/--async` 参数退役，分别使用明确 `--source`、有界 `sync --start/--end` 和报价 `--workers`。`update --source tdx` 不接受历史日期。SQLite `sync` 使用同步历史读取，暂不支持 `--async`；`--workers` 控制报价连接数，K 线/BaoStock 读取及数据库写入保持串行。

## 指标来源与依赖

- 报价成交量按手转为股；MAC K 线成交量已经是股，不再乘 100。
- `update` 直接保存报价的 `vol_ratio` 与 `turnover_rate`，来源标为 `tdxman:quote`，缺失补算不会覆盖这些源值。
- `sync` 的收盘量比为当日成交量除以前 5 个有效交易日成交量均值；不足 5 日保留未知。
- MAC 历史 K 线包含该日流通股本时，将万股转为股，换手率为 `volume / float_share * 100`。没有可靠日期股本时不使用当前快照倒填，保持未知；保留已有直接来源指标。
- 成交量、日期股本或有效交易身份改变，触发当日指标；成交量前驱变化还刷新最多后续 5 个有效交易日量比。相关日市场汇总在同一事务内更新，无变化不写时间戳。
- 价格、参考价、日期 ST 等继续使用既有 MA20/连板后缀依赖。超出既有读取、日期或事务预算时回滚，交给显式维护，不自动扩大到全历史。

北交所仍获取报价/K 线和涨跌收益，但统一标为 `NO_LIMIT`，不进入涨跌停、连板和晋级统计；取不到记录时保存 `MISSING`、保留已有行情，不伪造已确认停牌或平价 K 线。BaoStock 不支持 BJ，备用源无法修复时继续保持 `MISSING`。缺参考价与缺行情分开，已有成交不能被改成停牌。

## 有界重试与失败报告

默认首次尝试加 2 次重试，退避 1、2 秒；可设 `--retries 0..5`、`--retry-delay 0..30`，单次退避最多 30 秒。连接失败、超时、协议读取失败、空/过时报价、空 K 线和不完整备用源日历可以重试，重试重建连接。部分报价返回时，只重试缺少的证券。

同源同键合法事件修订正常合并，并重算有限因子后缀及派生。`update` 优先比较报价昨收与本地上一有效收盘，仅在存在除权嫌疑时查询该证券近期除权事件；`sync` 按输入窗口核实近期事件。缺返回不自动删除旧事件。业务输入拒绝先回滚该组，再剔除拒绝证券提交其余证券；数据库故障和事务超时仍中断，不自动重试。读取与等待发生在写事务外。全市场按最多 500 股一组提交，后面组失败不撤销已经成功的组，报告保留已完成组。

当前日期、有效零成交快照记 `NO_TRADE`，不作为读取失败重试；缺失或过期响应有界重试，最终记 `MISSING`。两者统计均按无交易处理，不生成平价 K 线。零散缺失完成后状态为 `completed_with_missing` 且退出成功；连续三只重试耗尽触发 `aborted_source_failure` 并返回非零。报告 `traded/no_trade/missing/invalid` 是收到的输入分类，实际提交证券及变化行数以 `success` 为准。

报告位于数据根上一级 `.local/reports/sqlite-update-*.json` 或 `sqlite-sync-*.json`，不进入 `data/`。包含源、请求范围、重试、失败/缺失、因子不可用及提交成本。部分失败返回非零退出码；不自动切换 BaoStock。`changed_rows` 保留源行变化计数，新增 `changed_metric_rows` 单独记录量价补算写入。

交易日通过有日期的上证指数报价或指数 K 线确认，只新增已观察到的开市日期，不从缺数据推断休市。新日期因子需要核实事件后才能延长；无锚点继续保持因子未知，不默认因子 1。质量原因列仅在数据库已显式升级时随汇总更新，本入口不偷偷升级结构。

历史 `sync` 每次最多 10 个输入交易日，通达信每股最多读取 1,024 根 K 线定位窗口，超限明确失败。大跨度离线初始化不属于日常 CLI 增量。普通读取和 Fundwise 消费不会触发采集。
