# DG-03：日线事实候选与架构决策

日期：2026-09-27。基线 `be60d78`。这是独立工作区的候选实验，生产入口与 `/home/ubuntu/.aspool` 均未修改；本轮完成实现和可审查实验，两个原型均不批准生产迁移；继续使用现有已验证后端。

## 决策

**拒绝把全局 DuckDB 表作为当前预算下的生产候选。** 在 5×、89,311,935 行、完整原始列、主键和证券 ART 索引保留时，正常全市场下一日 7,266 行的单事务提交在 SQL 1 GB 内存上限失败。分批构造能得到测试库，不能用分批提交偷换正常 `apply` 的原子契约。

**按月 Parquet 备选也暂不准入。** 完整字段与原子多月发布已实现，实际完整公开路径和恢复验证已执行；修正比较配置后，近期 60 日保留原双线程/512 MB 的中位约 0.821 秒，1× 已达到建议 1 秒目标；单证券经历初版 7.06 秒、物理键下推单线程约 2.22 秒、原双线程约 1.214 秒，仍明显慢于原按证券 Parquet 约 0.158 秒。每次真实修订复制完整约 933.5 MB catalog，是此参考原型显著的额外维护成本。不能凭扫描范围改善就宣布已经选定上线布局。

日常全市场读取和原子事实修订优先；单证券、ETF、事件消费作为独立反向负载考核。没有真实调用频率，不捏造百分比权重或加权总分；正确性和可恢复性失败不能由快查询抵消。后续 DG07 的明确阻塞是：在固定预算保持单批原子性、给单证券可接受访问路径、消除或取得业务批准的 catalog 复制成本，并完成统一公开入口与生产消费接线。此次不继续扩展第三套存储系统。

## 已确认的契约与实现边界

候选 `src/aspool/dg03_candidate.py` 保存 40 个原始列，另外用 `__market`、`__code` 保存路径键，主键为 `(__market,__code,trade_date)`，证券访问另建 `__code` ART 索引。原物理 `symbol`、`code`、`date`、`datetime`、`vol`、`float_shares`、来源列及 ETF 标识均保留，不用公开投影替代原始 schema。每个原文件的完整 Arrow schema（含 metadata）保存在实验根的 `source-schema.json`。

原 catalog 整体复制，因此日期事实、生命周期、交易日历、发布、stale、所有原约束均保留；没有依据新日期或证券号推断日历、ST、生命周期。非日线索引与其他 lake 数据保持原布局和读取接口。候选完全由固定恢复快照生成，不成为第二个生产权威。

公开读取保留 35 字段、单位、NULL、源字段、日期边界、日期事实/有效发布参考价覆盖、股票/ETF 过滤、重复键与数值校验、50 万行 DataFrame 限制。冻结复制的研究读取经 AST 检查确认仅 storage bind 与最终 overlay 两处替换，其他步骤与原方法一致；复制仅用于隔离评估，正式演进仍须通过统一存储入口接入，不能长期维护两套公开实现。

候选 `apply` 是显式、已规范化事实变更集合的事务入口，并非网络抓取或 DG01 合并/质量报告接口。普通 merge 忽略缺失值，清空/删除必须显式指定；raw 与 `domain='facts'` 可同批提交，revision、变更日志、coverage 和保守已发布日期 stale 后缀共同提交。仅值修订不扫描历史刷新 coverage，普通新增/内部删除由元数据增量维护，删除边界或 coverage 缺失才进入该证券范围修复。Universe 等维度保留输入快照，不能从合成证券制造新事实。依赖指标完整变更集合与派生重算仍由 DG05/DG06 负责，不能把存储候选记作它们已完成。

## 全局 DuckDB 增长、更新与恢复

1×/2×/5× 扩大 `dg03_daily` 的完整 42 列以及 truthful coverage 日期/计数；完整原始源列仍在，逻辑 `trade_date` 每份偏移 40 年。`date`/`datetime` 等原扩展不伪造重算，因此这些是压力数据，不是有效市场史。更多证券场景复制全部 raw，使用全局唯一六位合成 code；原 catalog coverage 的 symbol 单列主键保持不变。日期事实单独 1×/2×/5× 扩大，其余 universe/lifecycle/calendar/derived/publication 保持固定真实版本，不外推递归产品增长。

2× 一次全 schema 追加成功，35,724,774 行，SQL 1GB、1 线程，构造阶段 69.228 秒、RSS 1,223,061,504 字节。5× 从 2× 前缀追加整份 17.86M 行，在 COMMIT 发生 SQL 内存 pin 失败（953.5/953.6 MiB），失败日志与完整 2× 已提交前缀保留，5× 目录原位续跑，未另存失败时的整库字节快照；没有移除主键、索引或提高预算。按源年份提交、每批关闭连接后，第三份数据成功，但第四份近期年段仍在 COMMIT 达到同一内存边界；失败时的部分提交库另存 `failed-5x-year-prefix`。进一步限定每批 128 证券，跳过已完成年份，内容与分批进度键同事务提交并闭连；已提交前缀中断/续跑小测通过，实际 5× 续跑单独记录。

## 按月 Parquet 备选

`dg03_monthly.py` 保留完整 42 列，不可变 ZSTD 月文件内按 market/code/date 排序，行组 32,768。原 catalog 的 18 表及其约束整体复制；月 manifest 以 month 为主键，记录相对路径、日期范围、行数和 SHA-256。每个新月文件校验主键唯一与日期归月，写入 staging 仍使用完整 raw 主键和证券索引；月之间日期互斥。Parquet 中没有持久全局 ART，不能称为保留了 DuckDB 候选的索引访问成本；原始生产 catalog 索引/约束没有被去掉。

公开读继续冻结的完整契约；manifest 先按日期选文件，证券请求另将原始 __market/__code 条件下推。ETF 有相同 public_read 错误包装；事件金额用日期选月、精确证券日期键 join，并继承发布/stale/revision 检查。merge/clear/delete 的逐行规范化与 DuckDB 共用；全 no-op 不复制 catalog，混合变更只发布实际变化的 raw 月，facts-only+raw-noop 不写月文件。独立审查的四项具体发现均已修复并用新定向用例验收。

发布协议：持整个 root 写锁 → 完整 catalog 私有副本 → 同批 raw/facts/coverage/stale/revision/audit → 生成新 immutable 月文件并 fsync → 更新私有 manifest → checkpoint/fsync → 保存旧 catalog hardlink → 原子 replace catalog → fsync 根目录。读者共享同一目录锁，见到的全部月份和元数据属于同一个 catalog。删除边界从未触碰月份的键/日期列修复 coverage，不能只用 staging 热月推断全史。

1× 321 个月、17,862,387 行，新月逐值双向 EXCEPT ALL、42 列 SQL 类型、日期范围、唯一键检查通过；18 原表全值相等。构造+核验 192.339 秒、RSS 1.411 GB；目录 2,307,346,094 字节，其中 catalog 933,507,072。2×/5× 使用已核验前缀独立文件副本并验证哈希，只对新增、真实偏移 40 年的冷月做逐值核验；无未偏移日期冒充历史。原物理 date/datetime 等源扩展保留不改，这些增长数据仍然仅用于压力测试。

## 迁移、回退成本与准入边界

算子 rows-scanned 不等于唯一物理行或设备读取量；日期段统计只给候选行组上界；内核 write_bytes 不等于 SSD 损耗，100 ms 磁盘采样会漏掉短峰值。maxrss 是进程高水位，操作采样 RSS 和 SQL 限额单独保留。近期读量受日期范围约束，但 native 大索引维护、monthly 整 catalog 复制和单证券文件绑定仍有独立增长成本。

迁移需要固定恢复基线、规范化变更重放、独立全字段迁入/核验、最终增量追平、统一入口与受控切换。观测构建/核验 native 初始 62.25+45.46 秒、月排序重建 65.82 秒、monthly 1× 192.34 秒；这些不是在线停机承诺。保留源与目标至少需要两套活跃数据容量，另有 staging、WAL、索引重建空闲块和旧 catalog/parts 留存。monthly 本参考协议每次真实事务约增加一份 933.5 MB 历史 catalog 加变化月文件，不做 GC；具体 12 次修订成本见增长表，不能按 2.3 GB 基础体积承诺长期容量。

切回旧 Parquet 要按保留的原 Arrow schema/schema metadata 保真导出更新后的全部事实和日期来源，或将切换后的变更重放回旧后端；不能把过期旧池复制成当前权威。原始导出/最终增量追平/生产切换窗口未实测。已实测的仅本机 native 4.881 GB 副本恢复 12.113 秒、monthly 2.307 GB active 副本恢复 8.176 秒。不能由这些数值声称在线逻辑 rollback 或跨盘恢复达标。

**已实现**：两种隔离候选、完整公开读取/事件路径、显式规范化原子变更入口、可运行增长/扫描/写入/恢复脚本与原始证据。**已检查**：本报告列出的 schema、结果、进程协议和数据量；失败项原样保留。**未准入**：全局 native 5× 整日原子提交；monthly 单证券退化及 catalog 写放大。近期1×同配置约0.821秒通过建议门槛，倍率结果另表，不混入单线程样本。网络合并/质量入口、指标依赖与递归重算、派生一致发布、全部消费者统一存储入口、GC/断电/远程恢复、生产迁移仍未验收，属于后续 DG05/DG06/DG07；本轮没有修改或切换生产。
