# 四表 SQLite 落地计划

日期：2026-09-28。已开始实施隔离 SQLite 核心及事实迁移，生产数据未改动。用户最新优先级：**数据迁移与其他 VPS 开发数据准备 → 核心派生 → 同步更新接口 → 先跑通 Fundwise 日频工作流**。迁移/异机执行入口见[数据先行开发说明](vps_development_data.md)。此文件替代旧 DG-03 月文件补做和 DG-06 发布代次扩建。详细依据见[数据迁移与接口评估](sqlite_migration_api_assessment.md)。执行规格见[详细需求与设计](sqlite_stock_requirements_design.md)，附[四表 DDL](design/stocks_schema.sql)和[完整模型模板](design/market_four_dimensions.v1.json)。

新版权威根固定为本主项目 `data/`，股票主库 `data/stocks.sqlite`；隔离迁移根 `data/_staging/fw02/`。旧 `~/.aspool` 只作为源/恢复材料。所有工作包遵循[路径契约](sqlite_stock_requirements_design.md#0-新版数据根tdxmandata)。

## 1. 必须达到的最终行为

1. stocks.sqlite 只有四张股票业务表：daily_bars、corporate_actions、daily_features、market_daily_summary。索引、SQL 临时表、SQLite schema 版本不是新增业务域。
2. 股票数据、逐股限价、公共市场特征经局部写入回调在同一事务提交；重复同样输入不写、不重算、不改变缓存时间。取消业务 batch_id、coverage/exceptions 实体与修订/发布流程。
3. 缺数据与明确停牌对涨跌、成交、连板统计完全同处理；补数后只改相应股票/日期和必要后续递推，不自动修订全部市场历史。
4. 日更一起生成 Regime 公共特征并更新相关周/月，包括涨跌停单列后的15档互斥分布；周/月区分15档日分布人次与13档原生周期收益人数。Fundwise 用模型模板支持 D/W/M 计算、复用公共特征与小型指数序列；模型权重、阶段评分、板块策略不进股票数据库。具体以[模型模板设计](regime_model_template_design.md)为准。
5. 整史导入、规则变化的历史回算、整库修复与压缩仅由外部 ops 脚本维护；业务入口没有 full/rebuild 或失败后自动全史兜底。
6. ETF、指数、分钟和公共证券目录/日历保留原接口与来源，不因为股票库四表目标删掉其他必要数据。

## 3. 正常更新的固定流程

```text
获取最近范围或明确补数范围（事务外）
  → 规范化并合并同股票同日输入
  → BEGIN IMMEDIATE
  → 与目标键比较，找实际变化（无变化即结束）
  → 更新 daily_bars / daily_features 的源字段 / corporate_actions
  → 按变化字段调用计算函数，写 daily_features 计算字段：当天限价、必要后续连板/窗口
  → 汇总实际受影响日期，同一天只聚合一次
  → 更新已支持频率的实际依赖周期（包括后续周期基准依赖）及 updated_at
  → COMMIT
```

失败 ROLLBACK；调用方重试相同输入即可，不为重试生成批次号。一次事务可接收当日所有股票，不等于业务批次；它没有供消费者连接的发布身份。若上游分段返回，先按日期收集有限输入再提交；只对已有有效样本做统计，不把“事务完成”标成“全市场历史完整”。

正常同步以已有证券末端为起点，默认重叠最近少量市场交易日；参数硬性要求明确有限日期，初步可采用最近 5 个交易日，最终按数据源修正规律在 S2 固定。无历史证券只抓业务默认近期范围，完整历史走 ops。细化设计给出初始输入/递推/事务预算守卫，S2 实测后固定，不代表已验证的性能。历史短区间补数同一路径执行，禁止隐式扩展全部历史。

变化字段分支保持简单：金额/换手更新日汇总；OHLC/参考价/ST 更新限价及其必要递推；公司行为调整相关参考价与滚动窗口。滚动状态和连板的影响范围分别计算，不把“连板相同”当作所有指标都可以停止的条件。历史修改可能影响下一根有效 K 线的参考价，必须包含这一条依赖。

MA20 结果缓存在 daily_features 的两个列；局部重算按最近 20 根有效 K 线读取；不再假设 60 自然日必然足够覆盖长期停牌证券。多证券同日输入合并后只执行一次该日市场聚合。截面中位数等可对受影响日重新扫描全市场必要列，范围是目标日及预热窗口，不能转成全年明细计算。

## 4. 外部 ops 的职责

拟新增 `scripts/ops/` 下的入口（尚未实现；迁移入口优先随FW-02交付）：

- `migrate_stocks_sqlite.py --source-root ... --target-root ...`：只迁到显式新目标，支持显式 facts/derived/verify 阶段：先迁入全部历史事实，逐股与日汇总计算就绪后有界回填派生；输出键/字段差异、未解决来源问题和计数。
- `rebuild_stock_derived.py --root ... --start ... --end ...`：明确范围的历史规则重算；整史模式只允许在这里，需协调停写及受影响消费者。
- `verify_stock_migration.py --source-root ... --target-root ...`：原始字段/公开读语义与新统计分别验证，不把旧批次整套带入新库。
- `backup_restore_stocks.py`：正确备份 SQLite、校验恢复、新库切换后增量导出与必要反向应用；备份不靠复制活跃单个 sqlite 文件。

迁移进度、源 manifest、日志和恢复材料保存外部文件，不在 stocks.sqlite 新建任务表、audit 表或 publication 表。源快照发生变化就明确重新计划迁移或按外部差异追平，不把迁移检查塞进正常日更。

完整股票迁入期间必须保持 ETF 分类隔离。旧 catalog 含公共日历、目录、指数覆盖等，股票域脱离不等于可删除整个 catalog。旧 adjustments 文件和 dated_inputs 在 corporate_actions 对账前保留。

## 5. Regime 接口交付

asPool 提供固定范围的 `read_market_summary(start, end, frequency, scope, fields, closed_only)`，`read_market_daily` 是日频入口，包含涨跌分布、量能、限价/连板梯队与 MA20 广度。初期 `scope` 为 all_stocks / exclude_known_st；不接受任意模型权重或任意全市场扫描表达式。D/W/M 主键与边界、NULL、样本分母、单位、ST 未知语义在 S1 固定，周/月进行中值不用于未来数据回填。

Fundwise 同一范围特征只读一次，供多个模型模板计算。模板文件定义特征、评分、权重与频率参数；模型结果缓存键包含模板内容/参数、频率、范围、公共特征定义、该范围更新时间以及使用的指数/成员依赖。历史新增特征在 ops 回填后才对外声明就绪。单纯改评分权重不触发 aspool 重算。指数日线在指数域按有限范围读取复用；不复制进股票四表。

股票特征与日线/限价读取使用同一读快照。模型运行较久时，输入已经物化为小型日序列，可以结束数据库快照；输出前重新检查相关日期的时间序列是否变化。主线排名仍使用逐股事件+金额有界接口，不能宣称仅日汇总可以替代板块成员运算。

v3 不制造 batch_id/stale=False 来欺骗旧消费者。旧应用在旧后端运行，新应用在隔离新库验证后协调切换；确需兼容的投影接口不恢复被删除的业务实体。

## 6. 数据验收：保留什么、允许改变什么

| 类别 | 验证内容 | 标准 |
| --- | --- | --- |
| 原始日线 | 每证券/日期/字段与源规范化结果比较；OHLCV/amount、别名、来源与扩展 | 不丢有效键/值；资产分类、单位、日期转换正确；源冲突有清单与明确处置 |
| 日期事实 | 源 pre_close/ST/trading_status、无日线事实、历史名称依据 | 来源优先级正确，不把 NULL 变 false，不把快照当历史事实 |
| 参考价 | 277,429 条现行参考价与事实/原日线映射 | 不因取消 publication 丢失有效修正；派生来源可随输入变化重新计算 |
| 公司行为 | 186,622 事件与 58,677 因子逐源比较、事件去重/同日多事件；对照 tick 单次因子→累乘→asof | 不重复复权；同表稀疏累计因子等于重建值；覆盖基准日、事件错日、历史更正、无变化输入；差异可解释 |
| 限价/连板 | 缺行=停牌、停牌占位、补入涨停/非涨停、首次历史边界、间隔除权、ST改变、无价格限制 | 增量计算等于新口径完整参考算法；旧规则差异单列 |
| 公共特征 | 收益/成交样本、MA20基准、ST scope、梯队晋级分母、中位数/极值 | 日汇总等于原始有限窗口参考计算；无效分母返回 NULL |
| 有界读 | 字段前推、同库金额 JOIN、空区间、单日超 max_rows、完整/提前退出 | 五年峰值 RSS ≤2 GiB；不漏行不重复，不保留未关闭 cursor |
| API | daily/research/ETF/index、lookback、fields、空符号、错误码、pandas dtype/attrs | 除明示 v3 变更外与当前契约兼容 |
| Fundwise 多模型 | 同特征不同权重、缓存命中、原始数据修正、指数单独修正 | 改权重不读全年股票；范围外变化不清全部历史；相关变化结果更新 |
| tick adapter | local 股票/ETF/指数数据单位和列、online 路由 | local 调用兼容；不重复声称 host 外部环境已通过 |

全量物理值对账不要求机械保留废弃别名，但必须有可审查转换和恢复源。新缺口/ST/MA20/晋级定义导致的变化单独列数和案例；数据不等值、算法口径变化、旧数据质量问题不能混成一个“允许差异”集合。

## 7. 性能、并发与恢复验收

先在 1× 真实完整股票数据上测一次基线，再用相关 2×/5× 增长验证热点成本。复用旧测试对语义的有效证据；SQLite 新事务、新规则与新接口必须有针对性新证据，不因 agent 交接重复已通过测试。

| 负载 | 重点证据 |
| --- | --- |
| 全市场新增一日 | 实际差异数、日期截面聚合次数、耗时、RSS、writer 占用、WAL 增量 |
| 同样输入重复一次 | changed_rows=0；业务记录/updated_at 不变；不调用派生；不重写冷历史 |
| 历史单股票单日补数/改价格/ST/金额 | 查询命中的键与窗口、后续递推停止位置、受影响日数量；不能因年数增加扫描全部日线 |
| 单股票 20 年 K 线 | 主键/索引命中，按列读取；不先查全池文件或全市场 |
| 一年公共特征 × 多个评分模型 | aspool 不读全年股票明细；数据库请求/返回行数及模型评分耗时分开记 |
| 五年涨停事件+金额 | 同一快照、稳定排序、完整迭代与 RSS≤2 GiB；并发写下结果不混合 |
| 新库持久化体积 | 四表及索引、WAL、临时文件分别计量；与旧原始 Parquet 不做不等口径比较 |
| 读写并发/两个 writer | 单 writer 串行与锁超时行为；长读 WAL 增长及释放后的 checkpoint |
| SIGKILL/计算异常 | 事务中断后 raw/facts/actions/limits/summary 全旧或全新；提交成功但响应丢失时重试无变化 |
| 备份、换目录恢复与回退 | 实际恢复读取与公开结果；切换后新写入不丢失；不依赖原绝对目录 |

维护计算初期沿用 1 个重任务、RSS 3 GiB 守卫作为实验约束；旧 DuckDB SQL memory_limit 不直接套成 SQLite 配置。具体正常日更时延、writer 最长占用和恢复耗时以 S2/S3 样本作为 S5 的固定对比基准，本轮没有虚构 SLA。发现不能达标时先优化范围和查询，不自动增加业务表/发布协议或提高资源预算。

## 8. 生产切换与删除顺序

1. S5-D 核心验收前只写独立 target；旧生产继续作为唯一权威。脚本必须打印并校验源/目标不同。
2. 维护窗口停旧写入并确认没有未决恢复，保存可恢复源与配置；最终迁入或追平只通过 ops。
3. 对同一冻结源验证新库事实与新派生；切换 aspool/Fundwise 配置和代码组合，关闭旧连接，清掉受影响旧应用缓存。不能仅替换文件而让进程继续持有旧 inode/连接。
4. 核验日线/指数/ETF、当天日汇总、一个历史区间、主线事件金额；开启正常局部 writer，验证一次更新和一次 no-op。
5. 发现问题先停新写入，保存切换后差异，再按已演练回退步骤恢复；不能直接启用过期旧快照。
6. 新链路与回退都验证后，先删除旧 API 依赖，再清理旧股票实体/副本；保留公共域与未结证据。此次规划不执行这些删除。

## 10. 首个里程碑 M1：先支撑 Fundwise

必须同时满足以下条件，不能只凭SQLite中出现四个表宣布可用：

1. **完整原始事实迁移**：冻结源的股票历史全部迁入，ETF隔离；事件、来源因子和无K线日期事实有明确去向。迁移拒绝/冲突逐项解释，不能用行数相等替代逐值对账。
2. **首期派生范围明确**：至少覆盖 Fundwise 实际所需的五年区间及必要前驱/20根有效K线预热；具体start/end写入验收报告，由冻结源实际历史确定。首次连板找可靠边界，否则如实未知；不得声称只算最近几日已支持五年回算。其余已迁历史派生由ops继续回填，公共接口对未计算范围报 FEATURE_NOT_READY，不自动全史计算。
3. **真实工作流**：Fundwise 在隔离新根上完成一次当日日频运行、一次历史区间回算；环境四维评分、周期/梯队、主线排名与报告路径均能产出（真实输入不足的部分如实不可评分），没有batch/coverage异常接口依赖。
4. **修订闭环**：补一日、改一日价格/ST/金额、删除一条错误输入均与新口径参考重建一致；缓存仅失效实际依赖。完全相同输入不改时间、不重算。
5. **接口与性能**：35字段旧daily兼容，ETF/index不退化；五年事件金额读取RSS≤2GiB；正常日更/单股历史请求无全市场历史扫描。文件锁/WAL及I/O须在实际tdxman/data文件系统验证；新SQLite机制只运行其必要测试；已有agent证据源码未受影响时复用，不重复跑。
6. **核心运维**：SIGKILL/事务异常不产生半事实半派生；备份恢复到其他目录成功；切换后新增输入可保全回退。1×真实数据与代表2×/5×增长测扫描/写入/计算/失效/恢复成本，超预算问题修复后才进入FW-07。

M1首发可以只支持日频：`describe` 明确 `market_frequencies=["D"]`，W/M报 FREQUENCY_NOT_READY；未回填的日期不伪造全零。表/字段存在不等于功能已经可用。一旦FW-08启用W/M，就必须同事务维护其依赖，不允许继续用旧D-only writer写入；升级入口按能力/schema兼容检查失败即拒绝，不能暗中留下过期周月结果。定义代码版本+根配置共同决定运行能力，不新增publication表。

W/M、多模型扩展与跨设备复制仍属于最终承诺；它们不作为M1阻塞项。若首个D版本切换生产，则对用户明确这是分阶段交付，并在FW-08/FW-09继续完成后续工作。
