# ST 缺失默认规则与 2026 年涨跌停修复

更新日期：2026-10-01。

## 当前判断规则

按用户要求，ST 依据缺失不再阻止涨跌停判断：

1. 使用交易日对应的可靠 `is_st` 记录。
2. 否则，使用当日名称前缀判断：`ST`、`*ST`、`SST`、`S*ST` 等。
3. 两项依据都不存在时，记录选定 `is_st=0`，来源为 `assumed:not_st`，按非 ST 规则计算。

`assumed:not_st` 表示默认假设，并非已验证的历史名称。原始 `source_is_st` 及来源保留；已有可靠 ST 记录不被默认值覆盖。涨跌停参考价、上市日期或规则依据缺失时，仍保留对应未知状态。

## 为什么此前数量偏少？

此前规则将缺少当日 ST 依据的股票标记为 `UNKNOWN/missing_st`，不计入涨跌停。2026-06-30 有 3,091 只股票因此未参与判断；7 月 6 日开始 ST 依据覆盖明显提高，造成统计数量突变。

## 本次生产修复结果

显式检查窗口为 2026-01-01 至 2026-09-30，仅修复受影响股票及连板依赖。

- 涉及 3,110 只股票，补齐 368,633 行 ST 选定值。
- 重算 371,798 行涨跌停及连板派生值。
- 更新 127 个交易日、两种 scope 共 254 行原表日汇总；影响日期为 2026-01-05 至 2026-07-15。
- 原始行情、原始 ST 证据、复权因子和 MA20 值不修改；不另建结果表。
- 此前的 6,482 日历史长度保持不变。2026 年以前的存量记录未在此次窗口内回填；新默认规则适用于后续计算。

全市场收盘涨停家数对比：

| 日期 | 修复前 | 修复后 |
|---|---:|---:|
| 2026-06-30 | 32 | 142 |
| 2026-07-03 | 20 | 108 |
| 2026-07-06 | 73 | 73 |

2026-06-30 和 2026-07-03 剩余各 105 只无法判断，原因为 `missing_reference`，不是 ST 缺失。SDK 已安装生产运行环境，公开接口读取结果已核对。

## 显式维护入口

```bash
python scripts/ops/repair_st_defaults.py \
  --root /path/to/data \
  --start 2026-01-01 --end 2026-09-30 \
  --report /path/to/repair-report.json
```

维护窗口最多 366 个自然日。脚本仅修改 `features.sqlite` 的逐股特征与原有市场日汇总，在写锁下执行；连板更正可传播到窗口后继，直到状态收敛。已存在周／月汇总时会拒绝执行，需对应周期维护入口。中断后可用同一区间重跑，已写入的默认选定值也用于定位待汇总日期。
