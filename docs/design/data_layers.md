# 基础数据与 Enriched 数据分层契约

日期：2026-10-02。本文统一项目文档的数据层术语，作为下一阶段增量同步的边界基线；增量同步实现与验收见[同步入口](../ops/base_data_incremental_sync.md)。

## 1. 两层定义

**基础数据**：全部个股、全部指数和 ETF 的历史 K 线，以及证券目录、交易日历、分类与成分来源快照、公司行为、下载的复权依据与外部来源锚点、财务报告、股东人数等输入数据。历史 K 线保存来源未复权价格；“全部”指覆盖目标证券集合和来源实际可得历史，不补造上市前或来源不提供的数据。

**Enriched 数据**：依赖基础数据和明确计算规则得到的衍生结果，包括本地计算的股票/ETF 复权因子、逐股有效参考价、交易/ST 判定、收益、涨跌停、连板、MA20、量比、基于同日来源股本与未复权收盘价计算的总/流通市值，市场汇总、板块日聚合，以及按需计算的指标快照。市场汇总即使作为下游模型输入，也仍属于 Enriched 数据。

“原始/来源数据”仅描述基础数据中的来源观测，不是基础数据的同义词。复权数据指下载的除权除息/公司行为事件、来源复权行情、来源累计因子或外部锚点等依据，属于基础数据；由这些依据计算得到的日期复权因子属于 Enriched 数据。即使来源字段名含 factor，来源观测仍按基础数据保存，与本地计算结果区分。计算证明与验证结论属于 Enriched 元数据，不能替代下载的原始依据。直接通过 `kline --qfq` 下载的 OHLC 是基础数据，保存在 `stocks.sqlite.stock_qfq_bars`；本地用基础 K 线和因子计算的复权投影属于 Enriched。不得将下载值仅保存在 Enriched 中，否则只复制基础数据无法恢复。

下载的 qfq 只保存每个证券、交易日的最新来源 OHLC，不复制成交量、金额，不建立多基准日价格矩阵。`source_as_of` 记录下载快照日期，用于避免混用不同来源快照；它不是额外的主键。发生来源修订时更新真实变化的行，并重算受影响的 Enriched。当前历史整治先覆盖五年，不新增 MA 等指标。

“派生数据”“衍生数据”“稳定特征”“Regime 公共特征”统一归入 Enriched 数据。缓存是存储与保留方式，不设第三个数据层；来源快照按内容归基础数据，计算快照按内容归 Enriched 数据。文件名包含 snapshot 不足以判断分层。

## 2. 当前物理所有权

| 层 | 唯一生产存储 | 内容 |
|---|---|---|
| 基础数据 | `catalog.duckdb` | 证券目录、交易日历、指数分类等来源元数据 |
| 基础数据 | `stocks.sqlite` | 个股未复权历史 K 线、下载的 qfq OHLC、来源公司行为 |
| 基础数据 | `indices.sqlite` / `etfs.sqlite` | 指数 / ETF 未复权历史 K 线 |
| 基础数据 | `fundamentals.sqlite` | 财务报告、股东人数历史 |
| 基础数据与 Enriched 数据混合 | `adjustments.sqlite` | 外部来源锚点/复权依据归基础数据；本地股票/ETF 日期因子与计算验证结论归 Enriched 数据。现存 ETF 迁移参考须按来源区分，不能仅凭表名视为本地可重建结果 |
| Enriched 数据 | `features.sqlite` | 带日期的来源事实归基础数据；逐股衍生、市场汇总、板块日聚合；计算所需的来源成分快照也在此库，逻辑归基础数据 |
| Enriched 数据 | `snapshots.sqlite` | 按需计算结果缓存；目前具备 schema，不代表计算命令已上线 |

层是逻辑职责，不要求立即移动表或重命名文件。`adjustments.sqlite` 同时含输入依据和计算结果，下一阶段须按表及字段划定增量载荷。`features.sqlite` 内的板块来源成分快照不能因库名被当作可随意重建的衍生成品；历史重算必须保留当时绑定，不能改用当前成分。物理所有权和一致发布以[单一权威存储整改](../implements/single_authority_storage.md)为准。

股票日线表中的 `total_mv/float_mv` 按来源字段分层：来源直接报价属于基础数据，`derived:raw_close*...` 属于 Enriched 数据，基础增量剔除后者并在接收端按同日依据重算。没有可靠同日股本时保留缺失，不能使用最新财务股本倒填历史市值。

Fundwise 的评分、阶段标签和结果缓存属于消费端计算结果，由 Fundwise 管理，不是 tdxman 的基础数据。

## 3. 增量同步的边界

区分三个动作：来源采集更新基础数据、设备间传递基础数据增量、本地计算更新 Enriched 数据。现有 `aspool update/sync` 会维护依赖结果，不等于已实现跨设备逻辑增量协议；此前八库完整复制是封闭成品复制。

增量同步遵循以下契约：

1. 按数据集、证券、日期和字段识别真实变化，传递新增与修订；删除必须有单独授权和明确协议，当前实现不传递删除，缺返回不能自动当作删除。无变化不改业务版本。
2. 下载的复权依据、外部来源锚点和来源成分快照纳入基础增量；本地因子按事件、锚点、价格依据和算法计算，再更新依赖因子的 Enriched 结果。不能仅传三类 K 线，也不能把来源修订误判为计算因子本身的新增。
3. 各数据域分别报告目标集合、来源可得历史、更新日期、缺口和失败。财务报告期、采集时间、交易日不能混用；股票日线最新不等于整个基础层完整。
4. 基础数据写入或修订的交付必须同时检查 Enriched 依赖结果；不得仅以基础表有值或 writer 成功判定整改完成。接收端基础数据完整发布后，按真实变化计算 Enriched 失效范围；先更新受影响的复权因子，再处理滚动窗口、连板后缀、市场和板块截面。未完成结果保持可识别的未就绪状态。
5. 选择接收端重算还是传递 Enriched 成品时，明确输入、规则与发布代次。接收端重算还需同版本规则、历史成分/ST 等依据；不能假定只凭 K 线即可完全重建。
6. 规定幂等重放、断点续传、一致发布与恢复、源端写入权限和消费者验收。全库文件哈希仅用于封闭复制校验，不作为业务失效依据。

分层不代表质量认证：不确定交易状态仅在现有计算中被排除，不能解释为已确认无交易，未知参考和无效价格保留原因；有行、有最新日期或 Enriched 发布成功均不能证明全部基础输入可靠。

## 4. 文档与实施边界

当前生产入口见[生产数据流契约](production_data_flow_contract.md)及[每日流程](daily_data_pipeline.md)。指数/ETF 稳定 Enriched、W/M 汇总、按需 snapshot 命令及跨设备自动调度仍须按部署环境验收；ETF 因子目前不是在线日更数据源。

历史设计、实施回执和审计保留当时的字段名、路径、数字与结论；其旧“来源层/参考层/缓存层”分类不覆盖本文两层定义。术语统一本身不要求迁移数据库 schema；配套增量 CLI 和发布保护的实际变更以实现与验收记录为准。

状态判断、转换、消费与十年检查见[证券逐日状态契约](security_daily_state_contract.md)。
