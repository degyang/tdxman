# CLI 帮助风格规范

本规范适用于本项目的 `tdxman` 和 `aspool` 命令行。帮助页的目标是让用户无需阅读源码即可确定命令用途、参数口径、可用值和可运行示例。

## 根命令与命令组

根命令或命令组采用以下顺序：

```text
Usage
一句话说明
Commands
Options
示例
```

`Commands` 按用户的操作目的分组；`Options` 只保留该命令组实际接受的选项。示例使用完整可复制命令。

## 叶子命令

每个叶子命令采用以下顺序：

```text
Usage
Options
参数说明或类型对照
示例
```

`Options` 使用 Click 的原始参数定义，包含默认值、取值范围和输出选项。参数说明解释位置参数、条件生效的选项、单位、时间口径和业务限制；类型对照用于市场、板块、指数等枚举值。示例至少提供一个完整命令，并优先使用 `--format table` 便于终端阅读。

## 内容要求

- 位置参数必须说明格式和代表值，例如 `MARKET=SH/SZ/BJ`、`SYMBOL=SZ000001`。
- 有条件的参数必须说明生效前提，例如 `sync --tdx-mode` 仅在 `--source tdx` 时有效。
- 数据存在实时、历史或收盘后限制时，必须在参数说明中写明。
- 类型表只能列出当前 CLI 实际可接受的名称；底层数值类型应明确标明数值调用方式。
- 不在帮助中描述实现协议、内部存储路径或未实现能力，除非它会直接改变用户命令的结果。

## 输出约定

`tdxman` 数据命令默认输出 JSON，可通过 `--format` 和 `--output` 控制终端及文件输出。`aspool query` 的默认输出为 table，其余 `aspool` 维护命令输出执行结果摘要。帮助页必须保持各自命令的真实输出约定，不为统一样式改变命令行为。

## 验收

每次新增或修改命令时，至少验证：

1. `--help` 中的区块顺序符合本规范。
2. 类型对照与参数解析保持一致。
3. 示例可以通过参数解析；涉及网络或数据池写入的示例不在帮助测试中实际执行。
4. 相应 CLI 单元测试和静态格式检查通过。
