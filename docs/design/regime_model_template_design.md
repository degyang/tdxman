# Regime 模型模板与日、周、月计算

日期：2026-09-28。状态：目标设计，尚未编码。用户新增要求：用模板结构保存模型，支持多模型和日/周/月计算。与[四表实施计划](sqlite_four_table_implementation_plan.md)一起执行，不增加第五张股票业务表。

## 1. 计算职责与存储

asPool 计算可复用的市场特征；Fundwise 保存模型模板并运行评分/阶段分类。日、周、月模型均优先读取已经计算的市场特征，不为每个模型反复拉全年逐股日线。

股票库第四张表保留现定名称 `market_daily_summary`，扩展为支持 D/W/M 的市场汇总。键改为 `(frequency, period_key, scope)`；`frequency` 为 D/W/M，period_key 分别为 YYYY-MM-DD、ISO 周 YYYY-Www、YYYY-MM。period_start/end 为日历周期边界，as_of 为实际计算到的市场交易日。已有日接口只选 D，不把周/月行混入。

其余三表为 daily_bars（日 K 与有日期依据的名称）、corporate_actions（原始事件/来源因子）、daily_features（合并 pre_close、必要 ST/交易状态和逐股日限价/连板）。不再单设 security_daily_facts 或 limit_events。周/月 K 线和周/月模型输出不再复制成股票业务表。

模板保存在 Fundwise 仓库 `config/regime_models/`（加载 .json 和 .yaml/.yml）（拟新增），加载为一个 `RegimeModelTemplate` 数据对象。评分执行器复用现有纯函数并按 calculator 名称分派；新增不同算法时注册一个明确的计算函数，不为每个参数组合写一个新类。模板不含任意 Python/eval/SQL。

模型结果保存在 Fundwise 的既有应用结果/缓存目录，按模型、参数、范围、频率区分；不进入 aspool 四表。模板版本是模型定义标识，不是数据发布版本；不恢复 revisions/publication。

## 2. 模板最小契约

| 字段 | 用途 |
| --- | --- |
| id / name / version | 模型身份、展示名称及定义版本；同时计算规范化模板内容指纹 |
| calculator | 固定注册的评分计算器，如当前四维评分；不得动态执行模板文本 |
| frequencies | 支持 D/W/M；未定义的频率明确拒绝，不悄悄按日模型运行 |
| scope | all_stocks 或 exclude_known_st；任意自选池另属研究模型 |
| inputs | 所需公共特征、单位、跨周期聚合方式、预热周期数 |
| dimensions / weights | 子维度组成、归一化区间与权重 |
| states | 分数到状态的区间，边界和优先顺序明确 |
| frequency_overrides | W/M 可覆盖窗口、阈值或权重；缺省继承必须在模板显式声明 |
| missing_policy | 输入缺失返回不可评分或明确的局部评分，不默认填 0 或 50 |
| output_fields | 分数、子分、状态、使用的频率/范围、输入截止日和必要解释 |

本轮已补充[完整模板样例](design/market_four_dimensions.v1.json)及[详细字段/接口设计](sqlite_stock_requirements_design.md)。样例以 JSON 保存，可作为 YAML 子集加载；包括全部输入映射、单位校验、四维权重/归一化、状态阈值、NULL 策略和 D/W/M 定义，不再引用未定义的 weekly_v1/monthly_v1 参数集。

D 公式来自当前 Fundwise score_market。W/M 使用每日涨跌比例的样本加权、每日收益中位数的均值、涨停日均人数、周期封板比例和期末高度/MA20；指数使用真实周期收益。显式沿用 D 阈值，标 experimental_uncalibrated。原生周期收益的中位数另有 period_median_return，不与日中位数均值混用。第二模板在 S4 通过改变权重验证共享输入；本轮不提前复制一套几乎相同的生产模板。

## 3. 周/月口径：每个特征必须明确

支持两类特征定义，但不混用名称：一类是“周期内日特征的汇总”，另一类是真实“该周期涨跌表现”。模板列出使用哪一种，asPool 公共特征列固定定义，不为每个模板保存一份相同特征。

| 特征 | 周/月默认或可选定义 | 禁止的做法 |
| --- | --- | --- |
| 成交额 | 周期内实际日成交额求和 | 对缺行补虚构成交 |
| 涨跌家数 | `period_up_count` 按每股周期收益判断；`daily_up_pct_weighted` 则明确是按有效日样本数加权的上涨比例 | 相加每日涨家数后称为本周上涨股票数 |
| 涨跌幅分布 | 日频涨跌停各自单列，其他按±10%内每2个百分点、平盘及两端，共15档；周/月日累计15档，原生周期收益13档且不设周/月涨跌停档 | 累加日分布后称为周/月股票收益分布，或裁掉±10%以外样本 |
| 涨跌停 | `limit_up_occurrences` 为逐日人次合计，`limit_up_symbols` 为周期内去重证券数；期末家数按 as_of 读取 D 行 | 把人次当股票数、用周 K 线代替每日限价判断 |
| 连板高度 | 期末市场交易日的最高板数，或周期内最高板数；模板显式选择 | 对每日板数相加 |
| 封板率 | 周期内封板人次总和 / 触板人次总和 | 无权重平均每日比例 |
| MA20 广度 | 默认期末日 MA20 广度；“20 周/月均线广度”是另一特征 | 把日 MA20 自动解释成周/月 MA20 |
| 均值/中位数 | 周期股票收益分布由逐股周期收益计算；日收益均值的周期均值另命名 | 用日中位数平均值当周期中位数 |
| 晋级率 | 明确可晋级样本分母；周期汇总按人数之和加权，期末值另列 | 把每日百分比直接相加 |
| 指数收益 | 周/月真实收益按周期前后有效参考价格或日收益连乘 | 把日收益率简单相加 |

真实周期收益取周期开始前的有效参考价格与周期内最后有效成交价格，调整到同一复权尺度；新上市缺少周期前基准则该项未知，成交额仍可统计。整个周期无有效成交的股票不进入周期涨跌样本。日期事实/除权信息不足导致无法确定价格尺度时保留未知。

日特征的周/月聚合只读日汇总；原生周期涨跌分布或涨停证券去重无法由日汇总还原时，在日更事务里读取受影响股票周期数据/必要前驱，统一计算并缓存该周/月市场特征。日更只涉及当日、所在周、所在月及实际递推/价格基准依赖影响的后续周期；历史补数同理。允许读目标周期的全市场必要列求中位数/去重，不允许每个模型都扫全年日线。

如果原生周期特征导致普通事务超出预算，先按实际使用模型收窄预计算字段并优化索引；长范围首次计算交 ops。不能静默退回“请求模型时全历史扫描”，也不能宣称未预计算特征已经可用。

## 4. 时间、缺口与模型窗口

- 按 Asia/Shanghai 的交易日处理。周采用 ISO 周一至周日，月采用自然月；周/月末是假期时以该周期最后实际市场交易日作为 as_of，不假造 K 线。
- 当前周/月可提供截至 as_of 的进行中结果，并标明 `is_closed=False`。is_closed 由周期日历、截止时间和保存的as_of是否到周期最后交易日共同判断，不引入发布状态机，也不因时钟经过周末重写无变化事实。正式回测默认只用已结束周期；中途周/月快照不作为未来已经知道的完整周期特征。
- 不维护历史每个盘中/周中快照版本；如果回测需要任意历史周中可见信息，使用明确 as_of 的有界重建，不能用最终周/月结果倒填。
- 20 日、20 周、20 月窗口含义不同，模板以“该模型频率的周期数”声明，并列出基础特征自身窗口。阶段连续两期确认分别表示两日、两周、两月。
- 缺行与确认停牌都不贡献当期交易统计；日连板冻结。周/月原生统计仍按本节规定的有效周期样本，不能因为资料未确认停牌而使用不同算法。
- 特征不可用或整个周期没有样本时输出 NULL/不可评分，不能借未来数据填补。W/M 的收益特征和日特征聚合不同，结果比较需使用同定义参考算法。

## 5. 目标接口与缓存

拟新增通用汇总接口：

```python
reader.read_market_summary(
    start="2025-01-01", end="2025-12-31",
    frequency="W", scope="exclude_known_st", fields=[...],
    closed_only=True,
)
```

start/end 对 D 为日期范围；W/M 选择周期并尊重 end 截止约束。若 end 位于历史周期中间，默认 closed_only=True 排除尚未结束的该期；不能返回期末数据。进行中实时请求只在保存的 as_of 不晚于请求 end 时可直接返回，否则报告不支持该历史快照，转明确研究/ops 重建。

`read_market_daily` 是 frequency=D 的便利接口；`read_limit_summary` 为其限价字段投影。Fundwise 拟提供 `compute_regime(model_id, start, end, frequency, parameters=None)`，从同一特征集合运行一或多个模板。参数变更只重算模型结果，已缓存的公共特征无需重算。

结果缓存身份包含模板内容指纹、实际参数、frequency、scope、period_key/as_of、特征定义及相关周期 updated_at；指数、板块等额外依赖分别加入。源修改一个日期只失效依赖该日期的 D/W/M 周期与模型滚动/递推后缀，不清全部模型全部历史。

## 6. 接入实施计划与验收

S1 即冻结 frequency/period_key 键、特征单位/定义和模板 schema，避免迁入后再改主键。S2 实现日特征和对应周/月有限聚合；S4 将 Fundwise 的硬编码评分包装为模板计算器，接入多模型和频率选择。完整历史的 D/W/M 初始化由 S3 ops 脚本完成；S5 验收以下场景：

1. 同一年度特征供两个模型复用，修改权重不重复读取全年逐股数据。
2. D/W/M 各自与独立参考计算一致；人次/去重人数、比例分母、中位数及周期收益不混用。
3. 跨年 ISO 周、节假日、当前未完结周期、上市/停牌/缺行、跨除权周期有明确结果。
4. 补一日行情只更新该日、所在周/月、依赖被修改周期基准的后续周期及实际滚动/连板后缀；无变化不写三类汇总。
5. end 位于历史周中/月中不读取未来期末结果；规则/模板或输入变化仅失效实际依赖缓存。
6. 多模型结果文件不会覆盖彼此；异常模板/未知特征/不支持频率明确报错。

模型可计算性、统计口径正确性、实际投资效果是三项不同结论；本轮只完成设计，不宣称模型已实现或周/月效果已验证。
