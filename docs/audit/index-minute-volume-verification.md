# 指数分钟成交量核验

2026-09-21；独立 Python 进程只读取 tdxman 数据，没有调用或修改 Tick Stock Panel。

## 结论

不能将本轮样本的指数分钟 `vol` 直接声明为手，也不能按股票规则除以 100。
四个核心指数、标准与 MAC 两种 K 线接口均出现 `vol ≈ amount / 100`。
这是成交额比例关系，不是已验证的成交量单位转换。
`UNIT_UNVERIFIED` 暂时保留；价格和成交额可读不等于完整八字段语义已经满足。

MAC 1MIN 与标准 1MIN 的量额合计相同；MAC 5MIN 的 48 根合计也吻合该量额比例。
日K amount 与分钟 amount 合计只有浮点编码级差异，但 vol 差异无法用统一的 1 或 100 倍换算解释。
这里不以日线/快照相互吻合单独证明其交易单位，而是用它们排除分钟数据的直接等价性。

## 分时接口交叉检查

标准 `get_history_minute_time_data(..., 20260921)` 的 vol 合计依次为：
94,681,885；108,469,408；52,525,599；30,792,066。
它们约为当日成交额除以 10,000，不能据此当作手。
MAC `get_tick_chart(..., date=20260921)` 的 vol 仍约为成交额除以 100。
另外，分时价格点首条标为 09:30，而真实分钟 K 线首根为 09:31，不能直接按相同时间键混拼。

## 端点与文档边界

CLI `tdxman kline` 对这些指数实际使用标准 `get_index_bars`，股票/ETF使用 MAC `get_stock_kline`。
切换成 CLI 的指数路径并不能消除本次样本中的成交量语义问题。

[通达信公式文档](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)
定义公式层 VOL 为手、AMOUNT 为元；这不证明未经转换的 TCP 响应字段采用相同口径。
本轮观察只支持“该字段与成交额高度成比例”，不把未确认的服务端设计原因写成事实。
